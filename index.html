Project Overview

This simulator demonstrates how a processor executes a program one instruction at a time. Every instruction cycle is broken into three visible stages — Fetch (bring the instruction from instruction memory into the IR), Decode (the Control Unit interprets the opcode and asserts control signals) and Execute (the ALU, registers and data memory carry out the operation) — with every register transfer logged step by step.

Learning Objectives

  • Trace how PC, MAR, MDR and IR cooperate during an instruction fetch.
  • See how the Control Unit turns an opcode into control signals.
  • Observe ALU operations, data-memory transfers and status-flag updates.
  • Understand sequential PC flow and how JMP / JZ change it.

    Flag rules (documented assumptions)
    • Z (zero) — set when the ALU result is 0.
    • N (negative) — set when the ALU result is negative (MSB = 1 in two’s complement).
    • C (carry) — 8/16-bit modes only. ADD: set when the unsigned sum exceeds the width. SUB/CMP: set when there is no borrow (first operand ≥ second, unsigned). MUL: set when the unsigned product does not fit.
    • V (overflow) — 8/16-bit modes only. Set when the signed result does not fit in the width (e.g. 100 + 100 = 200 in 8-bit).
    • In unbounded mode only Z and N are produced; C and V are shown as “—”.
    • Flags are updated only by ADD, SUB, MUL and CMP. JZ reads the flags but never changes them.
    Model assumptions
    • Harvard-style memory: instruction memory and data memory are separate. The PC indexes instructions (0 to N−1); data memory has 256 byte-sized cells (addresses 0–255).
    • PC advance: the PC is incremented during Fetch (step 5); jump instructions overwrite it during Execute.
    • Address units: one address = one instruction (instruction memory) or one value (data memory). There is no byte-level addressing or word alignment.
    • Cycle: one instruction cycle = Fetch + Decode + Execute. A “clock cycle” in a real processor is a single hardware timing step — several clock cycles make up one instruction cycle.
    • HALT is counted as an executed instruction; a program that runs off the end without HALT reports an error instead of halting cleanly.
    • Infinite-loop guard: execution stops with an error after 10,000 instructions.
    How to use / quick start
    1. Pick an example program (or press Edit Program and write your own), then Apply.
    2. Press Step Stage three times to watch one full instruction cycle: Fetch, Decode, Execute.
    3. Use Step Instruction for whole instructions, Run for continuous execution, and the speed slider to slow things down for your demonstration.
    4. Change the arithmetic width, initial PC, register values or memory contents in CPU Configuration.
    5. Watch the log, the summary panel and the highlighted data paths in the diagram as the program runs.
    Limitations
    • Simplified single-cycle educational model — no pipelining, caching, microcode, interrupts or I/O.
    • Only 11 instructions and 4 general-purpose registers; no shift/logic operations, no stack, no indexed addressing.
    • Control signals are a simplified textual representation, not a real micro-operation sequence.
    • Instruction memory holds decoded instruction objects, not binary machine code (no assembler encoding).
